# Привязка F_OP к фактическому каноническому runtime

18.11.2026 · E03_2026-11-18_03. Локальный аудит машинного кода, без сети и без замены scorer.

## Что проверено

CLT CPython 3.9.6 / arm64 / macOS 26.2. Полные пути, хеши исполняемого файла и модулей, копии бинарников и выделенные arm64-срезы сохранены рядом с `runtime_binding.json` в каталоге попытки. Это stronger evidence, чем имя функции, API docstring или тест нескольких списков. Исходник другой версии Python не используется.

* math extension SHA256: `fdf75c6e44a518c2fbf3c35d45c3b81973155ab4996fbd2843cee5e242136e26`.
* Срез arm64 math SHA256: `5a88f440ec6064e9d646340acd04465057c59da6e9b6f8ebedc696313e6bb5b3`.
* Загруженные инструкции math.fsum [0x2f28,0x3410), 1256 bytes: `800e36e0c4c39efa027efd14b0faaf4e86864569a7bffc3c7603edaa70428914`.
* CPython framework SHA256: `2c18a05ddf0b2ca36caeb9215089cd0016df53a1cb9042fee4a1395a0228ea1d`.
* Загруженное окно float multiply [0x5a104,0x5a284), 384 bytes: `4e4d66e7fe730d76ae5fb492c19512b3ba64053d450c8e73ec702063f5c01ac6`.

Через PyCFunctionObject.m_ml прочитан фактический адрес math.fsum; проверены имя fsum и flags=8. dladdr связывает указатель с загруженным модулем; адрес относительно base равен 0x2f28. Не используется ошибочное заключение из ближайшего экспортированного символа PyInit_math. Через offsets **локальных 3.9 headers**, полученные compiled helper, прочитан float.tp_as_number->nb_multiply: 0x5a104. Тождество выбранных машинных bytes памяти и arm64 файлов проверено. Полная функция fsum и нормальный float×float путь включены в окна; всё multiply окно не объявляется полной функцией.

Объектная аллокация/счётчики ссылок не меняют числовой результат при успешном выполнении. Произвольные пользовательские типы не входят в числовую область теоремы.

## Среда и доверенная часть

Compiled helper `scripts/c1_fp_environment_probe.c` **только читает** FPCR/fegetround и offsetof; не меняет режим и не перехватывает scorer. На обоих концах аудита FPCR=0, fegetround=FE_TONEAREST=0; sys.float_info radix=2, mant_dig=53. Для ARM64 FPCR=0 выбирает RN, без flush-to-zero; операции D-регистров binary64. Доказательство использует стандартную семантику IEEE/ISA и успешное обычное выполнение CPython, не доказывает исправность CPU/OS/allocators.

Guard среды включает стабильность режима и кода внутри защищённой области. Snapshot до/после не выявит переключение и восстановление FPCR посередине; поэтому сторонние callbacks/FFI/handlers, которые могут это сделать, исключаются явным контрактом worker. Непроверенная среда → UNKNOWN. Проверка соответствия future E04 реализации этому контракту ещё не выполнена; переход с backend на другой runtime требует нового binding audit или выключения BOX. Exact fallback остаётся каноническим, а не математически переопределённой суммой.

Сопоставление ветвей с алгоритмом выполнено вручную и документировано; это не доказательство в Coq/Lean и не автоматически сертифицированный дизассемблер. Числовое доказательство не опирается на плотность/неперекрытие partials или на эмпирический успех испытаний. Более грубая F_OP допускает ошибку каждой фактически указанной операции и весь возможный пропущенный хвост.
