## Почему статические reverse-search правила здесь безопасны

В исходном reverse MIPS кандидат проверяется относительно top-k item thresholds. Здесь item становится **документом**, score — max по всем его фрагментам, users — зарегистрированные запросы. Нельзя считать k фрагментов одного документа k свидетелями. Нижняя граница B4 строится только по различным применимым документам старого снимка. В sample меньше ell допустимых документов ⇒ -∞, отсечения нет. ell — длина точного старого резерва, минимум k при использовании конечного порога.

Основная адаптация — границы относятся к **замороженному старому порогу допуска в резерв**, а не выдаются за текущий top-k после удаления. Пусть b — полный ключ последней записи старого exact prefix R. Кандидат с K_new≤b должен быть учтён по L5 E03. Нижний numeric sample threshold B4 ≤ score(b); B5 использует score(b) точно. Поэтому строгий UB<threshold доказывает K_new>b и позволяет не вычислять его точный max. Равенство не отсекается из-за UTF-8 ties.

Старые изменённые строки удаляются из R независимо от отсечения новых; при недостатке k survivors выполняется **полный текущий поиск**. Именно это сохраняет корректность при потере прежнего witness/применимости/удалении лидера. Старый порог не используется как утверждение о текущем top-k; такое применение было бы неверно. L5 применим к полному D и точным survivors, поэтому C_q остаётся exact prefix. Registry/config changes полностью перестраиваются. Это доказательство безопасности адаптации на уровне алгоритма, затем проверенное differential suite; оно не утверждает побитный/временной паритет с программами авторов.

## Верхние границы и общее усиление

Точная Cauchy граница использует squared norms над Fraction и sqrt_upper через целочисленный isqrt с округлением вверх. Для block максимум query norm² и каждого фрагмента документа даёт upper exact dot; отдельная E03 ошибка canonical score включена через α_p A+β_p. A можно ограничить той же Cauchy величиной, поскольку Σ|q_i x_i|≤||q||||x||. Для документа берётся max по всем фрагментам. Дополнительно доступна общая абсолютная box support bound; минимум двух безопасных upper bounds безопасен. Эти геометрические примитивы не закреплены исключительно за C1. При неопределённости или выходе за guards кандидат проходит exact scoring.

Исходные float32/Eigen dot не используются: они не удовлетворяют E01. Все методы имеют одинаковый native binary64-products + настоящий math.fsum kernel, один поток, фильтры до max/ranking, полностью определённые ties. Исправлены известные проблемы демонстрационного кода: последний user в block, остаточный block, малый/пустой корпус, совпадающие scores, отрицательные значения; maps keyed only by score отсутствуют. Нет заявленного нового численного контракта ради удобства BLAS.

## Контроли C1

* FLAT использует тот же predicate/box/witness, но перечисляет doc postings перед проверкой Cert. Факторизованный C1 пропускает cell postings заранее.
* SEPARATE использует отдельные upper(z) и lower(w), те же E_x, blocks и strict comparison; paired correlation не используется.
* MARGIN имеет оплачиваемую полную score table и per-query gap/norm-delta попытку; если она не проходит, сравнивает реальные old/new canonical cached scores. Стоимость новых columns не скрывается. Это сильный cache-backed контроль, не обещание отдельного blockwise ускорения.
* NO_CERT отключает сертификат при том же точном engine. UNCACHED является самой активной C1 политикой: межпартийного certificate cache нет, отдельный дубликат не создаётся.

B2 fixed/adaptive и параметры B6/blocks ещё не выбраны на validation. Пилот и сравнение полного пути относятся к E05/E06; здесь подтверждена локальная исполнимость и контрактная корректность на предусмотренных проверках. Внешняя репликация/оптимальность реализации аналогов остаются ограничением любых будущих заявлений.
