# C1: полная стоимость и предел экономии

A-E03-C1-0.3-bounded-fsum · E03_2026-11-18_03. Наблюдаемых замеров времени/RSS нет. Ни один порядок сложности не подменяет первичный lifecycle-критерий E02.

## Параметры

M запросов, n документов, N фрагментов, p координат; B блоков; r=Σ|R_q|; c=|D|; t_d=|R_d|+|A_d|; a_delta=Σt_d; a_star=Σ текущих фрагментов изменённых документов. V — byte-size истории идентичностей/текстов для version validation, Wemb — модель и workspace; Eemb — создание нужных embeddings. Cmax — лимит числа успешных клеток Cert (по умолчанию 2^20, стоимость записей зависит от представления).

J — число попыток BOX для пар z,w; P_scan — число scores отдельного SCAN-контроля (в основном BOX-пути равно нулю); P_exact — scores exact engine для несертифицированных клеток; F — число полных INITIALIZE. Z_fail — число postings, открытых у UNKNOWN клеток. Δr — суммарное число old/new reserve memberships, обработанных при изменении R. Сравнение длинных IDs/текстов имеет цену по байтам; O(1) ниже относится лишь к фиксированным machine words.

## Создание

Полная инициализация: O(MNp+Mn log(n+1)) для прямого точного scorer+сортировки, плюс Eemb и чтение/валидация. Bounded top-cap допустим как общая оптимизация. Query partition с точным выбором ширины и пересортировкой на каждом уровне стоит O(Mp log(M+1)+M log²(M+1)) сравнений/координатных действий; boxes O(Mp log M) покрыты этим верхним пределом. Точная диадическая ширина/сравнение имеет bigint цену при реализации Fraction. Построение postings O(r log(r+1)) для persistent balanced map. Предобработка не исключается из таймера.

## Партия

1. Прочитать/валидировать все входные байты, ordered events, версионный реестр, создать embeddings и staging. Сформировать полное D и S/R/A с проверкой содержимого. Если нет достоверных изменений/identity ledger, нужен полный diff. Для изменённого документа это может стоить чтения всех его фрагментов и текста, а не только t_d.
2. Для каждой из Bc клеток проверить guards; lookup/вставка Cert O(log(Cmax+1)). Пустое S или metadata mismatch обходится без scores, но обход клетки/документа не бесплатный. Указанный алгоритм не обещает sublinear число клеток.
3. **Основной BOX в спецификации:** J≤B a_delta проверок, каждая вычисляет support/A_z/A_w за один проход p координат. F_OP аффинна; α_p/β_p предвычисляются один раз на размерность/context постоянным числом рациональных операций, без L=p(p−1)/2 итераций. Цена J·C_bound(p,K), где для прямого Fraction C_bound=O(p·(Mul(K)+GCD(K))) как консервативная битовая оценка. K=O(2148+log p+размер коэффициентов α/β); коэффициенты заданы фиксированными рациональными выражениями с O(1074+log p) bits. Exact dyadic products имеют знаменатель до 2^2148, поэтому O(p) действий не означает O(p) дешёвых SIMD-инструкций. A_w можно кешировать на одну клетку; это не меняет верхнюю оценку. Нет обхода q и нет вызова canonical scorer внутри BOX.
4. **Runtime и отдельный SCAN-контроль:** привязка/хеширование бинарников и проверка конфигурации оплачиваются один раз на numeric context, проверка FPCR — перед/после защищённой области в том же worker. Сам локальный исследовательский дизассемблер не запускается на каждой партии; будущая программа должна реализовать проверяемый контракт окружения, включая отсутствие смены режима внутри области. Недопустимая среда/параметры дают UNKNOWN, расходы не исключаются. При явном выборе SCAN `P_scan≤Σ_attempted(d,b)|Q_b|(t_d+1)`, в грубом случае O(M(a_delta+c)p) canonical scoring плюс точные разности; witness cache стоит O(|Q_b|). SCAN не включён скрыто после неуспешного BOX и не считается O(B a_delta p).
5. UNKNOWN клетки: O(Z_fail) перечисления query memberships плюс exact scoring O(P_exact p), где P_exact≤M a_star без фильтра/повторного reuse, и добавление кандидатов. Документ удалён или неприменим — scores не нужны, но зависимости обрабатываются. Фильтры одинаковы у всех методов.
6. Для Touched просмотреть старые R и собрать/отсортировать кандидатов: O(Σ_T |R_q| + Σ_T (|R_q|+h_q) log(|R_q|+h_q+1)), где h_q≤c. Membership в D_q требует проверок D и Cert; balanced-map log factors оплачиваются. Full fallback дополнительно O(F(Np+n log(n+1))). Даже если SCAN уже просчитал часть этих scores, повторные расчёты нельзя исключать из времени без реально специфицированного cache.
7. Incremental persistent postings: O(Δr log(r+1)), включая поиск различий old/new R. Неизменённые поддеревья разделяются, изменённые пути копируются. Если будущая реализация копирует весь r, добавляется O(r); это не «та же нулевая цена». Конструирование root tables O(M+n) при прямом копировании ссылок. Полный вывод/оговорённые чтения Ω(Σ min(k_q,eligible_q)) плюс bytes IDs/версий.
8. Registry/cap/config changes в простой спецификации выполняют полный rebuild всех активных q; этот неблагоприятный режим не исключается из отчёта. Если оба пути не завершаются/OOM, новая версия не публикуется; бесконечного ускорения нет.

Все члены складываются вместе с Eemb и валидацией. Вложенные интервалы не суммируются повторно при будущем wall-clock lifecycle-измерении.

## Память

Корпус O(Np) и тексты/метаданные; запросы O(Mp); резервы+postings O(r); boxes O(Bp), membership O(M); identity ledger V. В партии дополнительно staging изменённых документов/версий, bounded Cert O(min(Bc,Cmax)), candidate records до O(Mc), full-search scratch O(n), root references O(M+n), path copies O(Δr log(r+1)), Wemb. Потоковый BOX держит постоянное число K-bit аккумуляторов/коэффициентов и scratch bigint операций; если реализация материализует массивы Fraction, добавить O(pK). Кеш A_w имеет цену одного K-bit числа на текущую клетку; кеш для всех клеток отдельно не обещан. SCAN-контроль дополнительно держит O(max_b |Q_b|) witness scores. Одновременно существуют старый и новый root; разделение памяти не отменяет цену изменённых узлов. Лимит retained roots обязателен, иначе reader retention делает пик неограниченным. Граница RSS≤16GiB и ratio≤1.2 — будущая измеряемая проверка, не следствие записи O().

## Польза, проигрыши, нижние границы

* BOX может избежать восстановления max по большому неизменному остатку документа, query-wise scoring изменённых фрагментов и обхода Rev у успешных клеток. Вместо |Q_b| парных score вычисляется support/A по p координатам. Это структурное сокращение работы; дорогие rational операции и сильный B3 со score cache могут устранить практическую экономию. Новая численная граница симметрично предоставляется всем сопоставимым геометрическим контролям.
* Если S пуст, witness плох, metadata/query/config часто меняются, blocks широки или много ties, платится неуспешный certificate work и почти весь исходный engine.
* Оценка F_OP порядка p²uA более консервативна, чем прежняя недоказанная 4u-гипотеза; почти равные scores могут чаще давать UNKNOWN. Это цена доказанного пути. BOX должен окупить init, source/identity validation, boxes, postings, numeric context и output. При общей неизбежной части >90% baseline total теоретическое устранение остатка не даёт прежние 10% полного выигрыша.
* B≈M, a_star≈N или F≈M дают полную M×N работу плюс overhead. Рост corpus не разрешает бесплатно знать изменившиеся/применимые пары.
* Ω(bytes input) и Ω(bytes outputs) сохраняются. Нет утверждения O(1) update и нет переноса вероятностного refill-анализа Yi на произвольные удаления.

O6 повторно закрыто как анализ спецификации: **доказанный BOX имеет цену O(p) точных координатных действий на пару и не вызывает query-wise scorer**, при оговорённой битовой цене и guards. Speedup, реальная доля успеха и RSS не измерены. Критерии E02, семь семей и все controls сохраняются. Реализация и выполнение полного пути относятся к E04 и последующим отдельным поручениям.
