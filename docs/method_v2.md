## 1. Неизменяемый контракт и состояние

Полный ответ, фильтры, max по фрагментам, UTF-8 ties, text_version, канонический scorer и кадровая область — паспорт 2.2/E01. Ключ документа `K=(-score,UTF8(doc_id))`, меньший лучше. Winner выбирается по `(-score,UTF8(fragment_id))`. Норма E01 с tolerance 1e-12 не является допуском ранжирования. Точная выдача не доказывает полноту компетенций/снижение кадрового риска.

R_q — точный префикс применимых документов длины ell≤cap; cap — конечное целое ≥k. Если ell<k, R содержит все применимые документы. Каждая запись хранит score, doc ID, winner ID и text_version. b_q — **полный ключ последней записи резерва**, не kth output. Пустому R соответствует b=+∞. Cap фиксирован; его явная смена в этой версии запускает полную инициализацию. Автоматическая адаптация Yi/cost-based switch выключена; обязательный correctness fallback действует.

Корпус, R, query registry, blocks, reverse postings и версии образуют immutable root. Один writer, закрепление корня читателем и ограничение числа retained roots/backpressure необходимы для ограниченной памяти. Новый корень публикуется только после полной проверки; отказ сохраняет старый снимок с прежней corpus_version.

## 2. Query blocks без бесплатного разбиения

Параметр leaf_limit — целое ≥1, по умолчанию 64, зафиксирован без данных о производительности. Построить balanced kd-разбиение: для узла вычислить точные диапазоны координат, выбрать максимальную ширину (при равенстве меньший индекс), отсортировать q по координате и UTF-8 query_id, разделить пополам. Остановиться при размере≤leaf_limit. У листа min/max каждой координаты взяты из его фактических конечных binary64 и включают все элементы; epoch и query versions фиксированы. Одинаковые векторы не сливаются семантически.

Структура и boxes доступны конкурентам. Переразбиение внутри обхода партии запрещено. В простом активном варианте любая регистрация/удаление/смена query version/filter/time/vector/k, cap или config вызывает полную инициализацию всех активных запросов и blocks; изменённый embedding config требует всех новых векторов. Это оплачиваемый консервативный режим, не обещание дешёвых произвольных registry changes.

Rev[(doc_id,block_id)] хранит query_ids, чьи R содержат doc, с полнотой и без дублей. Small хранит ell<k. Индекс — persistent balanced map; публикация сохраняет старую версию. Перестраивать/копировать весь r индекс после каждой партии и не считать это время нельзя.

## 3. Документный сертификат и S/R/A

Сначала применить **всю упорядоченную партию** к staging и получить полный D, включая metadata/versions и net-same события. Валидировать IDs, version aliasing, исходные тексты, векторы и конфликты. Вне D сырые записи неизменны. Внешнее изменение правил применимости должно раскрыться в D либо вызвать полный rebuild.

Для существующего d в обоих снимках при полностью одинаковых метаданных выделить S: записи фрагментов с тем же ID, text_version, исходными байтами текста, битами vector и config. Совпадение hash — только ускоритель с проверкой содержимого. Old-only/changed-old = R_d, new-only/changed-new = A_d. Эти множества относятся к конечному состоянию, не к промежуточным операциям. Свидетель обязан принадлежать S; из удаляемого/переверсионированного witness сертификат не строится.

Если S пуст, документ появился/удалён, metadata различаются или нарушен epoch/config — UNKNOWN для клетки d,b. Если R_d∪A_d пусто при S непустом, сертификат выполняется без scoring. Иначе h=1: выбрать минимальный UTF-8 ID в S; выбор не знает будущего winner. Для каждого z∈R_d∪A_d и всех q∈Q_b требуется `s(q,z)<s(q,w)` с проверенным U_can<0. Равенства не принимаются. Более одного witness допускается теоремой при полном покрытии, но не включено в активную политику h=1.

**BOX_CANONICAL** — основной backend спецификации: вычислить точный рациональный U_can из `numeric_certificate_C1.md`, §7, с доказанной оценкой F_OP, и принять только U_can<0. Guards: проверенный numeric context/бинарный runtime, стабильная RN binary64 среда с gradual underflow, конечные координаты |x_i|≤2 и 1≤p≤2^20, фактический неизменный box. Проверка сборки оплачивается при создании context, режима — в том же worker перед/после защищённой области без меняющих FPCR callbacks; неизвестная среда даёт UNKNOWN. Файл `fsum_runtime_audit_C1.md` фиксирует привязку. Коэффициенты α_p/β_p вычисляются точно один раз на p. При неуспехе клетки используется прежний exact engine; SCAN не запускается скрыто. **SCAN_CANONICAL** сохраняется как явно выбираемый дорогой контроль. U_real и прежний недоказанный U_cond не принимаются. Все численные/ресурсные ошибки означают UNKNOWN либо отказ публикации, если точный путь тоже не завершается.

Сертификат живёт одну партию и включает old/new corpus version, doc, block epoch, query/config versions и идентичности z/w. Материализуется только множество успешных клеток Cert; отсутствующая клетка означает UNKNOWN. Входной memory budget ограничивает число клеток (по умолчанию 2^20 записей); после достижения лимита остальные клетки получают UNKNOWN без эвикции уже используемых сертификатов. Цена хранится в RSS; исчерпание не даёт права считать клетку успешной.

## 4. Применение сертификатов к точному engine

Для каждого стабильного q определить `D_q={d∈D: (d,block(q))∉Cert}`. Вне D_q **производная запись** документа для q неизменна: либо d вообще не менялся, либо двусторонний сертификат доказал равенство. Сырой текст документа вне D_q может измениться; прежняя формулировка C0 о неизменности всех сырых полей поэтому не переносится буквально.

Границы b_q и старые R/Rev заморожены до окончания партии. Touched начинается с Small. Открывать Rev[d,b] только для несертифицированных клеток; включать перечисленные q в Touched. Нельзя сначала обходить все query postings и затем записывать это как устранённую работу.

Для каждой несертифицированной клетки и каждого q её блока вычислить текущий **полный** document max по всем фрагментам d, если он существует и применим. При K_new(d)≤b_q добавить текущую запись и q в Touched. Фильтр проверяется до ранжирования. Для сертифицированной клетки не удалять прежний d из резерва и не добавлять дубликат.

Для каждого q∈Touched сформировать `C_q=(R_q\D_q) ∪ {d∈D_q: eligible_new(d) и K_new(d)≤b_q}`. Если |C_q|≥k — оставить первые min(cap,|C_q|) по полному ключу; иначе полный INITIALIZE на конечном снимке. Незатронутый q сохраняет R. Короткие R входят в Small даже при пустых postings.

В persistent Rev удалить/добавить memberships только изменившихся R; обновить Small, record versions и границы для **следующей** партии. Цена сравнения старого/нового R и map path copying включена. Подготовить полные ответы с текущей corpus_version и опубликовать единый root. Сертификат одного документа не разрешает пропустить другой изменённый документ, а сертификат одного блока не разрешает удалить d из глобального D.

## 5. Границы результата

Логика обработки вставок/удалений, winner/reserve fragment, metadata, mixed batches, versions, ties, query/config changes и fallback разобрана и доказана в `proof_obligations.md`. Известные неверные упрощения сохранены как контрпримеры. Это доказательство спецификации при sound certificate и валидных входах, не проверка E04-программы.

BOX проверяет пару z,w по p координатам box без перечисления q; стоимость точных целых, runtime guards, построения и неудачных попыток явно включена. Его O(p) относится к числу арифметических действий, а не к сравнению времени с SIMD scorer. У SCAN нет такой экономии. Новизна support-function bounds/резерва/partitioned postings не заявляется. Аудит O7 не обнаружил доказанного эквивалента центрального оператора в прочитанных Simpfer++/Yi, но международный приоритет и эмпирическое преимущество остаются открытыми. Одна и та же новая безопасная граница предоставляется всем сопоставимым контролям.

Возврат RW_A_E03_2026-11-18_02 закрыт. Далее предстоит реализовать и проверить numeric guards, сертификат, exact engine и конкурентов. E04 автоматически не запускается.
