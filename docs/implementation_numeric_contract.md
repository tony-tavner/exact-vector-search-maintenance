# Числовой контракт реализации E04

A-E04-0.1, 18.11.2026. Основание — E03_2026-11-18_03, без изменения его канонического оператора.

## Почему пакетное ядро сохраняет score

`src/pvldb_a/native.c` принимает приватные C-contiguous native binary64 матрицы. Для каждой пары создаётся tuple ровно p произведений в прежнем порядке координат. Две соседние координаты вычисляются `vmulq_f64`; нечётный хвост — отдельным double multiplication. При FPCR=0 каждое lane выполняет тот же binary64 RN продукт с gradual underflow, что и Python float×float. Нет суммы в SIMD, FMA или перестановки координат. Tuple состоит из plain PyFloat, на нём вызывается **тот же объект builtin math.fsum**, сохранённый при загрузке расширения. Результат переносится в binary64 output без округления.

Следовательно это канонический score по построению, а не приближённый BLAS dot, проверенный лишь на конечной выборке. Векторизация касается произведений, матричного обхода и снятия Python цикла по координатам; суммирование остаётся настоящим fsum. Аллокация tuple/float объектов имеет цену и может ограничить производительность. Называть ядро BLAS/GEMM нельзя.

Фактическое дизассемблирование сохранено в E04 attempt/native_disassembly.txt: `fmul.2d` по адресу 0x90c и scalar `fmul` 0x988, чтения FPCR, вызов сохранённого callable через inline PyObject_CallOneArg/vectorcall dispatch. FMA инструкции отсутствуют. Сборка: -O3 -ffp-contract=off -fno-fast-math, matching CLT 3.9 headers. Module source/hash/binary/compiler записаны в environment/manifest.json и build_02.json. Доверенная часть — стандартная IEEE/ARM64/CPython семантика и корректность обычного исполнения; формальной ISA верификации нет.

## Что реально проверяет программа

`NumericContext` сверяет Python version, SHA256 исходных модулей, bytes загруженного fsum и идентичность callable, не подменяет scorer. `region()` привязана к worker thread, проверяет FPCR=0 до/после; native matrix дополнительно проверяет FPCR внутри вызова. GIL не отпускается. Автоматический GC временно выключен; trace/profile/custom Python signal handlers отвергаются. Входы Engine ограничены plain JSON primitives; пользовательские __float__/итераторы не исполняются. Внутри вычислительной области нет пользовательских callback hooks/BLAS.

Невыполнение обязательной среды scorer приводит к отказу до публикации. Если не подтверждена численная предпосылка BOX либо его область координат/размерности, BOX даёт UNKNOWN и работает exact engine. `disable_box` позволяет проверить этот путь без изменения scorer. Runtime/config changes требуют нового полного снимка/перестроения; перенос на другую сборку требует новой привязки. Проверка FPCR по краям сама по себе не доказывает, что режим не меняли посередине: программа исключает поддерживаемые источники таких callbacks; вмешательство стороннего native кода вне API не покрывается.

## Реализация F_OP и сертификата

`numeric.py` вычисляет точные α_p,β_p из E03 F_OP, кэширует их по p; коэффициенты не подбираются. В одном проходе по box считаются support/A_z/A_w над Fraction, затем принимается только точный знак U_can<0. float-конверсия для принятия решения отсутствует. Guards: 1≤p≤2^20, конечные координаты в [-2,2], корректный box, подтверждённый context. Невыполненное условие/равенство → UNKNOWN. Аллокационная ошибка abort до commit также безопасна.

Сохранение S требует ID, text_version, **имеющихся исходных текстовых байтов**, bits вектора и config. None/отсутствующий text не считается равенством исходного текста: такие старые учебные fixtures проходят полный точный путь. Для нового positive fixture исходный синтетический текст указан явно. Битовый identity различает +0/-0; порядок score не имеет epsilon. Версионный AVL ledger проверяет также промежуточные события партии и прежние удалённые версии; подмена payload при прежнем ID/version/config отвергается.

Последний тестовый запуск содержит побитное сравнение 315 матричных пар, оба исходных canonical-tie counterexample, финальную поправку fsum, 32 точных совпадения production bound с E03 формулой/128 пар scores, guarded fallback. Конечные тесты дополняют приведённую конструкцию и доказательство E03. Они не устанавливают ускорение или общую надёжность платформы.
