# C1: инварианты, доказательства и проверка восьми обязательств

A-E03-C1-0.3-bounded-fsum · E03_2026-11-18_03 · 18.11.2026. Входной перечень A-E02-C1-0.1 сохранён неизменным; результаты — `candidate_C1_obligations_E03.json`.

## Предпосылки и область

Корпус конечен, IDs уникальны; все векторы/версии/метаданные валидны по E01. Scorer детерминирован в фиксированном config/runtime. Старый R_q — точный префикс; при |R_q|<k он содержит все применимые документы. Партия валидируется целиком; D полно, вне D сырой снимок неизменен. Смена query/cap/config в выбранной спецификации вызывает полную инициализацию. Roots атомарны, один writer, отказ не публикует новый corpus_version. Эти условия требуют реализации/проверок E04 и имеют цену; сейчас доказывается спецификация.

Обозначим производную запись `V_q(d)` как ⊥ для неприменимого/пустого d, иначе `(score,doc_id,winner_id,text_version)`. Совпадение V включает representative/version, не только число. Ключи разных документов различны благодаря doc_id.

## L1. Численная безопасность BOX и SCAN (C1-O1)

В `numeric_certificate_C1.md` доказаны P1–P3 для каждой add/sub/sub тройки, ограничены масса partials, signed drift, неиспользованный хвост и финальная поправка. Это даёт F_OP для каждого допустимого списка округлённых произведений. Предпосылки привязаны к фактическим локальным инструкциям и FPCR в `fsum_runtime_audit_C1.md`; произвольная версия math.fsum автоматически не допускается. Через отдельную ошибку произведений и точный support box получено для каждого q: s(q,z)−s(q,w)≤U_can. Значит U_can<0 даёт строгий канонический порядок для всех q блока. Ошибки округления и subnormal не поглощаются произвольным epsilon, overflow исключён по guard и индуктивной оценке.

При неизвестной сборке/необеспеченном режиме, выходе за guard, ошибке или U_can≥0 сертификат не выдаётся; используется exact engine. Невозможность обеспечить фиксированный scorer/config запрещает публикацию как и прежде. Проверки FPCR по краям области дополняются инвариантом отсутствия его смены внутри. Runtime, продуктовый оператор, версии и память — оплачиваемые условия спецификации, которые ещё предстоит обеспечить E04-программе.

Для явного контрольного backend SCAN каждый конечный score непосредственно вычислен канонически, а max точных рациональных разностей по q безопасен по определению. Он не называется дешёвым BOX. Новая L1 даёт именно то универсальное строгое отношение, которое использует неизменная L2; остальные доказательства не нуждаются в конкретных коэффициентах F_OP.

## L2. Полнота S/R/A и неизменность max (C1-O2)

По уникальным ID и полному равенству записей old=S∪R_d, new=S∪A_d, части каждой стороны не пересекаются. Одинаковые векторы при разных text_version не попадают в S. Все фрагменты с изменёнными полями принадлежат соответствующей стороне delta. Delete+insert внутри партии оценивается по конечным old/new записям; промежуточная запись не может служить сохранившимся witness.

Пусть для каждого z из R_d и A_d существует w_z∈S, который строго лучше z для **всех** q блока. Для фиксированного q ни один z не может быть максимумом своей стороны: есть более высокий score в S. Поэтому старый и новый победители выбираются из одного и того же S. Scorer и правила UTF-8 tie-break одинаковы; записи S, включая version, идентичны. Значит совпадают winner ID, text_version и score. При одинаковых метаданных применимость также одинакова: либо обе V равны ⊥, либо одинаковой полной записи.

Доказательство разрешает разные witnesses для разных z; активный h=1 — частный случай. Если S пуст или кто-то не покрыт, вывод не делается. При пустых R_d/A_d условие соответствующей стороны пусто; если обе пусты и S непусто, вывод непосредственен. При равенстве score strict certificate не проходит, поэтому появление меньшего fragment_id не пропускается.

## L3. Покрытие query blocks и lifetime (C1-O3)

Каждое деление упорядоченного списка пополам образует непересекающееся покрытие родителя; база — весь стабильный registry. Индукцией каждый q содержится ровно в одном листе. Покомпонентные min/max взяты из самих элементов, следовательно каждый вектор внутри box без округлённого сужения. Выбор координаты по точной ширине влияет только на эффективность.

Epoch фиксирована на партию, сертификат содержит версии обоих снимков и всех зависимостей. Registry/config/cap change в активной спецификации не использует эти сертификаты и выполняет полную инициализацию. Старые блоки не изменяются во время отбора. h=1 выбирается из S по ID с платным просмотром, а не по неизвестным winners. Смена witness или его версии разрушает S-членство, а значит вывод L2 недоступен. После партии сертификат не переиспользуется.

## L4. Сокращение D до D_q безопасно (C1-O4)

Определим `D_q={d∈D: (d,block(q)) не сертифицирована}`. Если d∉D_q, то либо d∉D и его сырой снимок неизменен, либо применима L2 и его V_q неизменна. Значит **вне D_q производные записи неизменны**, что достаточно для поддержания top-k. Это более точное утверждение, чем неизменность исходного текста: текст непобедившего фрагмента может измениться.

Сертификат блока b1 не даёт этого свойства для b2. Поэтому удалять d из глобального D нельзя. Также неизменность одного V_q(d) не доказывает неизменность выдачи q при изменении других документов. Оба неверных обобщения имеют сохранённые контрпримеры.

## L5. Exact prefix после партии (C1-O5)

Для стабильного q пусть b — полный ключ последней записи старого точного R. Неизменённые в производном смысле документы вне R имеют K>b либо по-прежнему отсутствуют в eligible. Документы R\D_q сохраняют актуальные записи с K≤b. Для каждого d∈D_q engine вычисляет полный текущий max/применимость и добавляет ровно те eligible записи, у которых K≤b. Поэтому

`C_q=(R\D_q)∪{d∈D_q∩Eligible_new:K_new(d)≤b}={d∈Eligible_new:K_new(d)≤b}`.

Последнее равенство использует L4 вместо буквального предположения C0 о неизменности raw docs. Пустой R имеет b=+∞; инвариант требует старое Eligible пусто, и та же формула верна. Полный tie key необходим; скалярная граница резерва недостаточна.

C_q — точный префикс текущего Eligible. Если |C_q|≥k, top-min(cap,|C_q|) сохраняет точный префикс достаточной длины. Если |C_q|<k, full INITIALIZE восстанавливает top-min(cap,|Eligible|); если |Eligible|<k, сохраняет всех. Временное истощение до конца партии не является моментом решения о fallback.

Touched полон: если старый резервный d попал в D_q, q перечислен в Rev[d,block(q)]; если появился кандидат K≤b, q включён при exact scan; Small включён безусловно. Для q вне Touched нет затронутых старых записей и новых кандидатов за b, |R|≥k, значит C_q=R. Пересмотр полных записей, а не только IDs, сохраняет версии.

## T. Полный ответ и атомарная последовательность

INITIALIZE устанавливает prefix, complete-record и posting инварианты. L1–L5 дают их сохранение при stable-registry партии с охраняемым BOX_CANONICAL, SCAN либо другим **доказанным sound** certificate. Неопределённые клетки идут exact engine, поэтому ложные отрицания сертификата меняют стоимость, не точность. Лимит памяти Cert тоже только добавляет UNKNOWN. Изменённые membership postings и Small обновляются в новом root; границы используются лишь в следующей партии. Для registry/config/cap changes снова применяется INITIALIZE. По индукции каждая успешно опубликованная выдача полностью равна full oracle на том же снимке.

Ошибка в staging оставляет старый root; это корректный старый снимок, не успешное обслуживание новой версии. Полная выдача по всем q может потребовать Ω(Σk_q) времени. Конкурентные reader roots требуют лимита/backpressure; бесконечная retention не допускает конечного memory bound.

## Все обязательные операции

Вставка/удаление документа, metadata change и пустое S → UNKNOWN/exact. Новый фрагмент покрывается на A, удалённый — на R. Изменение winner не может получить strict certificate против сохранившегося худшего фрагмента; поэтому запускается exact path. Непобедивший/резервный fragment может быть безопасно пропущен лишь по L2. Version-only change выигравшего фрагмента не сохраняет его в S, даже при тех же bits; tied candidate также не покрывается строго. Mixed batch оценивается по конечному снимку; h/witness выбираются после этого. Query/config/partition изменения handled by rebuild, не stale сертификатом.

## O6–O8 и решение

O6: `complexity.md` пересчитан для активного в спецификации BOX, включая точную bigint арифметику, α/β, runtime/context guards и неуспешные проверки. SCAN остаётся отдельным дорогим контролем. O7: аудит `method_independence_E03.md` сохранён по смыслу; численная безопасность сама по себе не устанавливает научную новизну. Общая граница предоставляется конкурентам симметрично. O8: вновь проверены прежние 16 сценариев/32 full snapshots и finite prefix lemma; новая граница проверена на обоих численных контрпримерах, positive/negative margins, subnormal/cancellation и срабатывании финальной поправки fsum.

Итого: **O1–O6/O8 закрыты на уровне спецификации в явной области и модели исполнения; O7 рассмотрено, мировой приоритет и превосходство остаются гипотезой**. Прежние L2–L5 не изменены по тексту; новая L1 подставлена в их предпосылку sound certificate. Это достаточный критерий E03: метод однозначно специфицирован и обязательная численная безопасность доказана в ограниченной области, вне которой работает UNKNOWN. **Gate pass; E04 не запускался.** Это не повышение implementation/novelty/experiments flags.
